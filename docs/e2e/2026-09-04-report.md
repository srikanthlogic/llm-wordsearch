## Findings

### F1. Community generation unusable: model allowlist mismatch (blocking)
The proxy allowlist (deployment env) permits only `openai/gpt-oss-20b:free`; the client default
is `google/gemini-2.5-flash:free` → every default user gets
`400: Model "google/gemini-2.5-flash:free" is not allowed. Permitted models: openai/gpt-oss-20b:free`.
Additionally, the Settings community-model dropdown (fetched client-side from
`openrouter.ai/api/v1/models?supported_parameters=structured_outputs`) does not contain the one
allowed model, so it cannot be selected in the GUI. `API_KEY` **is** configured (the 400-vs-500
ordering in the handler proves it), so only the model name is wrong.

![generation error toast](./t2_loading_state.png)

### F2. Dark mode split-brain: styling rides on the Tailwind Play CDN
Production has no build-time CSS. `index.html` loads `https://cdn.tailwindcss.com` at runtime and
an inline `tailwind.config = {...}` script that throws (`tailwind is not defined` on every load)
because it executes before the CDN defines the global. Consequences:
- The CDN falls back to `darkMode: 'media'`; all `dark:` utilities follow the **OS** setting,
  while the app's inline CSS variables follow the **`.dark` class** the app toggles.
  Verified via stylesheet inspection: JIT output uses `@media (prefers-color-scheme: dark)`.
- The in-app Light/Dark toggle only half-works: e.g. the confirm dialog stays white on a dark UI.

![dark theme with white dialog](./t5_dark_theme.png)
![white dialog on dark UI](./t5_clear_confirm_dialog.png)

Every load also logs: `/env.js` 404 + `Refused to execute script ... MIME type ('text/plain')`.

### F3. Language switch unmounts the whole app
`I18nProvider` gates its children on `isLoaded` and re-enters the loading state on every language
change, so the entire tree below it unmounts. `App` remounts with fresh `useState`:
changing the application language in Settings ejects the user to the Maker view and loses all
form state. Verified: no navigation event; heading goes from "Settings" to "Creador de Juegos".

![after language change](./t5b_after_language_change.png)

### F4. History date grouping: "Yesterday" shown for a game played seconds ago
`HistoryPanel.formatDate` uses `Math.ceil(diffTime / 86_400_000)`, which is ≥ 1 for any positive
elapsed time — the `diffDays === 0` ("Today") branch is unreachable.

![history yesterday bug](./t4e_history_after_win.png)

### F5. Missing i18n keys (8) render raw keys; `|| fallback` is dead code
`t()` returns the raw key when missing (truthy), so patterns like `t('player.history.today') || 'Today'`
never fall back. Missing from `en.json`:
`help.loading`, `maker.gridSize` (slider aria-label), `maker.result.levels` (base key),
`maker.subtitle` (visible on the main screen), `player.history.today`, `player.history.yesterday`,
`settings.aiLogs.description`, `settings.aiLogs.viewButton` (visible in Settings).

![raw subtitle key](./t1_maker_initial.png)

### F6. Hardcoded English strings in dialogs on localized UIs
`App.handleClearData`'s `confirmDialog({ title: "Clear all application data?", ... })` renders
English while the rest of the UI is Spanish.

![english dialog on spanish ui](./t5_clear_confirm_dialog.png)

### F7. No victory screen
Completing the last level returns straight to the Player Hub — no celebration or stats summary.
(The win *is* recorded in history correctly; an earlier apparent loss of the record was an artifact
of killing the test browser before localStorage flushed.)

### F8. Shared games cannot be saved; print worksheet unreachable
No Save action exists in the shared-game session (a code comment claims one does), so a shared-link
player cannot keep the game, and the print-worksheet flow (per-game action in the library) is
unreachable without working generation.

### F9. Minor
- Generation error toasts hide the server's specific reason (model-not-allowed vs no-API-key).
- AI logs are session-only; a reload erases the diagnostics for the failure you just saw.
- Wrong word selections clear silently — no negative feedback.
- Keyboard play for the grid is not supported (cells are focusable divs but arrows/Enter do nothing).
