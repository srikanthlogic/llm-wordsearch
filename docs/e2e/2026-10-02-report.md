# E2E Test Report — WordKey v2 on production (post-release pass)

- **Date:** 2026-10-02
- **Targets:**
  - `https://llm-wordsearch.vercel.app/` (production, WordKey Playground, author mode, commit ≈ 4c7991d)
  - `http://localhost:4173/` — the built `dist/` served with a **serve-mode** `wordkey.config.json` + the sample corpus, to exercise the self-host path (serve-mode home, corpus-derived play, PWA) without an LLM key
- **Method:** Black-box GUI testing (ZCode in-app browser, desktop 1366×900 and mobile 390×844). Real mouse/keyboard/coordinate interactions only; read-only DOM checks for state verification. No code was modified during the test pass.
- **Evidence:** this directory (`docs/e2e/2026-10-02/*.png`), referenced inline.

## Environment prep (disclosed)

- Production was tested as-is.
- Local serve-mode instance: `npm run build`, then `dist/` served with a serve-mode config override (`mode: "serve"`, 2 levels/domain, 6 words/level) + `public/corpus/*` copied into `dist/corpus/` via `vite preview`. This makes corpus-derived play reachable without an LLM; it does not pre-complete any behavior under test.
- The self-host Hono server (`server/index.ts`) was attempted for the same purpose and **crashed on startup** (F2), so static preview was used for the client-side flows; server-only features (`/api/admin/corpus` publish round-trip) could not be tested and are covered by the F2 issue.

## Findings

### F1. Community generation dead in production: allowlist pins a retired model (P0, blocking)
The deployment allowlist permits only `openai/gpt-oss-20b:free`; OpenRouter now returns
`404: This model is unavailable for free. The paid version is available now - use this slug instead: openai/gpt-oss-20b`.
The client default `google/gemini-2.5-flash:free` is also no longer on OpenRouter's free tier.
`API_KEY` **is** configured (the request reaches OpenRouter), so every default user's generation
fails. `/api/llm-proxy/allowed-models` works and faithfully returns the dead list.

![generation failure with AI log](./t2_ai_log.png)

Fix direction: update the deployment env (`COMMUNITY_MODEL_NAME`/`COMMUNITY_ALLOWED_MODELS`) to a
live free model with structured-output support (e.g. `google/gemma-4-31b-it:free`), update repo
defaults + docs, and surface the upstream "use this slug instead" hint instead of a raw 404.

### F2. Self-host server crashes on startup: double `listen()` (P0, self-host path)
`serve()` from `@hono/node-server` already starts listening; `server/index.ts` then calls
`server.listen()` again → `ERR_SERVER_ALREADY_LISTEN`. Both `npx tsx server/index.ts` and the
Docker CMD (`node dist-server/index.mjs`) crash on cold start. The integration job only builds
the image and never runs it.

```
Error [ERR_SERVER_ALREADY_LISTEN]: Listen method has been called more than once without closing.
    at Server.listen (node:net:2044:11)
    at main (server/index.ts:181:10)
```

### F3. `localStorage is not defined` noise at server startup (P1)
`services/storageService.ts` runs `migrateStorage()` at module load; in Node the
`isLocalStorageAvailable()` probe throws `ReferenceError: localStorage is not defined`
(caught and logged). The server boots, but every start prints a stack trace for a
browser-only concern.

### F4. `bg-ink text-white` buttons are unreadable in dark mode (P1, a11y)
`--ink` flips to near-white (`rgb(232 236 242)`) in dark mode, so `bg-ink text-white`
renders white-on-white. Verified on the Owner gate **Unlock** button (enabled, but looks
disabled) and Trophies **Share my badges**. The design system already has
`--ink-on-accent-rgb` ("fixed dark ink on the highlighter") for exactly this.

![unlock unreadable](./t5_owner_gate_settled.png)

### F5. Badge toast shows raw `{{domain}}` placeholder (P2)
Winning a domain toasts **"Badge earned: Domain Master: {{domain}}"** — the interpolation
arg is not passed at this call site (the trophy shelf card interpolates correctly:
"Domain Master: ai-basics").

![raw placeholder toast](./t6_level2_complete.png)

### F6. Game Info drawer is exposed to assistive tech while closed (P2, a11y)
The clues drawer renders off-canvas (`translateX(320px)`, computed rect x=390 on a 390px
viewport) but has no `aria-hidden`/`inert`, so screen readers and the a11y tree announce a
dialog that isn't visible. Its only opener is the status bar — which is hidden on mobile (F9).

### F7. Model dropdown stuck at "Loading models…" when the allowlist fetch fails (P2)
With `/api/llm-proxy/allowed-models` unreachable (local static preview), the community
model select shows "Loading models…" indefinitely — no error state, no fallback to the
saved/default model.

### F8. Serve mode has no history UI (P3)
Wins are recorded (`wordSearchGameHistory` has the entry) but the serve-mode Player home
offers only domain cards + progress; the history panel exists only in the playground
Player hub.

### F9. Mobile: status bar (timer, word count, clues affordance) hidden under the tab bar (P1)
Both are `fixed bottom-0`: BottomTabBar at (0,761,390×84, z-50) covers the StatusBar at
(256,796,134×48). On a phone the player sees no timer, no words-found counter, and cannot
open the clues drawer.

![mobile game without visible timer](./t10_mobile_game.png)

### F10. Game Info drawer is translucent in light mode — text collides with page content (P3)
The opened drawer's `bg-sheet/85` panel lets the page heading and grid letters show
through the "Game Info" title and clue text.

![translucent drawer](./t11_status_drawer_desktop.png)

### Observations (not filed as bugs)
- **Swallowed clicks (intermittent):** two first-clicks on nav/segmented buttons were dropped
  (Settings nav, Light theme button; both worked on retry), and Playwright locator clicks time
  out app-wide while coordinate clicks and `selectOption` succeed — consistent with elements
  moving on hover (e.g. `hover:-translate-y`) or constant re-render. Needs a code look; if it's
  a render loop it's also a perf issue.
- **First-paint flash:** on a cold load the page paints light-gray before the dark theme applies (~1s).
- Console listening is not exposed by the test tooling; error evidence was gathered from visible
  page state and the app's own AI log.
- True offline/PWA-update flows could not be emulated; SW active + 24 precached entries verified.
