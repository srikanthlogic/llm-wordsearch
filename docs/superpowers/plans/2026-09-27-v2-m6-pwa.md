# WordKey v2 — Milestone M6: Installability / PWA (Implementation Plan)

> **For agentic workers:** subagent-driven or executing-plans task-by-task, checkbox tracking. **Repo loop:** one task = one issue = one branch/PR into `dev`, CI green, ledger. Verify: tests locally; tsc/lint/build in `/tmp/ws-clean`.

**Goal:** WordKey installs to a home screen, works offline for seeded corpus play (deterministic derivation + cached corpus/locales), and tells the user when a new version is ready.

**Architecture:** `vite-plugin-pwa` (workbox `generateSW`, `registerType: 'prompt'`) precaches the build and runtime-caches `locales/*`, `corpus/*`, `wordkey.config.json`, `vocab*` (stale-while-revalidate / cache-first per type). The manifest title comes from the build-time `public/wordkey.config.json` (read in `vite.config.ts`). The **esm.sh import map is removed** (the Vite bundle ships all deps; the import map is dead weight and blocks offline) and the CSP is tightened + `worker-src 'self'` added, in vercel.json, netlify.toml, and the Hono server.

**Spec:** `docs/superpowers/specs/2026-09-27-v2-reposition-design.md` rev 4 — §8, §7.4 (self-containment).

## Global Constraints

- Update flow = explicit prompt (`registerType: 'prompt'`, no `skipWaiting` races).
- CSP changes land in vercel.json, netlify.toml, and server/index.ts in the same commit (lockstep rule).
- Manifest name/description derive from `public/wordkey.config.json` at build time; fallback keeps v1 naming until M7 rebrand.
- New dev dependency allowed: `vite-plugin-pwa` (pulls workbox). Nothing at runtime.
